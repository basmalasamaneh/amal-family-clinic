Findings / limitations requiring follow-up (no production fixes made)
--------------------------------------------------------------------
1. Empty-submit error discoverability gap in this representative run.
   English submit at 05:34:08.116 and Arabic submit at 05:34:37.135 produced
   no recorded automatic error announcement before the next focus probe
   (~2.2 seconds). Error text was read on English field refocus and Arabic
   password refocus. Recommend a separate focused investigation of submit
   focus management/error summary or live announcement rather than claiming
   all dynamic validation is automatically announced.
2. Arabic email validation refocus at 05:34:39.343 has no corresponding new
   SPEECH OUTPUT line. Its initial label is evidenced, but this run does not
   establish the Arabic email error announcement. Treat as inconclusive.
3. TOC navigation in both locales generated verbose section-content speech
   followed almost immediately by its heading, sometimes concatenating
   number/title/Planned without spacing. Example: '2Who can see whatPlanned
   heading 2'. This is a reader-output usability observation; no audible
   intelligibility assessment or severity certification was performed.
4. Orca next-heading h probes from the table region produced no new transcript
   line in either locale. They are NOT a passing heading-navigation result.
   No table-cell/header navigation was executed; only region labels are covered.
5. Initial login was Arabic, but only English received sequential Tab traversal.
   Arabic received targeted focus/activation probes; no claim of full RTL
   sequential focus-order validation.
6. No authenticated-role, booking, reception workspace, admin workspace,
   mobile reader, cross-browser reader or NVDA/VoiceOver behavior was tested.
