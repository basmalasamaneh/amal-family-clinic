1. Before touching any records

  • Open the private app already provided and docs/SELF_TEST_DATA.json for patient/appointment IDs, dates and assignments. Start with the twelve existing accounts below. No need to recreate prepared records. This guide contains no passwords, PIN values or device credentials.
  • Existing owner-controlled operational data plus additive synthetic practice records are not assumed disposable or safe to reset. Preserve existing records; change only selected practice records. Use realistic names without “demo” or “test”; never contact a real patient or guess remote IDs.
  • Reception at three locations, network administrator, three clinic administrators, five doctors, future booked appointments, ten waitlist entries, consent/history and exact duplicate pair already exist. Original import export has 24 rows. Use manifest identity facts, never guesses.
  • Only missing special cases need preparation: minor/guardian, different same-name people, merge blockers, Reem and safely linked cross-location patient. Create synthetic cases via existing UI where supported; otherwise record Blocked and obtain owner/developer assistance. Never manufacture access by booking guessed IDs.
  • Use two separate browser profiles or different browsers for simultaneous users. Two ordinary tabs share sign-in cookies: one tab's sign-in/out can change the other. Use a third profile for doctor plus two reception users. Private windows may share one private cookie jar and discard offline storage; avoid them for persistence checks.
  • Record profile A (first reception), B (second reception/doctor), C (administrator if needed). Enrollment belongs to the exact profile on the reception computer. Use Asia/Hebron times; calendar weeks start Saturday, KPI weeks Monday.
  • Do not clear site storage/cookies, uninstall, merge, leave the network or reset during early checks. Do not run scripts, migrations or database commands. Missing/disabled features are Blocked, not passed.

Your paper record

Mark every check Pass / Fail / Blocked / Not run. Record ID, role/profile, clinic, Palestine time, synthetic record/operation IDs, exact actions, expected/actual result, screenshot filename and follow-up owner. Never capture credentials, PIN entry, cookies or private export contents.

Stop immediately for wrong-person data, unauthorized clinical notes, a silently disappearing booking, duplicate accepted retry or unsafe merge. Preserve evidence/profile; do not hide a failure with reset.

2. First session — do these in order

Allow an unhurried session. This is an order of work, not a time guarantee. Stop at missing prerequisites instead of inventing data.

  1. Open online: at /login, administrator uses Email and password → Sign in. Check identity/role in Account and display; choose English initially.
  2. Enroll reception profile A: on that actual profile sign in as administrator, Users & devices → Devices → Enroll this browser, select clinic, enter allowed Device label (for example reception-desk), complete enrollment, then Sign out. Device cookie remains; administrator session does not.
  3. Reception sign-in: choose Reception PIN; verify Trusted device for clinic; enter assigned Email / Four-digit PIN → Sign in. No free clinic impersonation. Separately enroll B if it will be reception.
  4. Orient: Help → Replay the guided tour; try Next / Back / Skip tour, replay and Finish. Read Your data. There is no patient login or patient portal.
  5. Schedule: in Today → Choose a date, select 22 October 2026 for future Booked cases. Inspect Doctor / All doctors, switch Day / Week and back. Inspect 21 October's Completed/No-show examples separately.
  6. Find: Downtown reception → Patient lookup, search ليان منصور, select patient 115 after matching manifest DOB/phone. Phone booking or New booking; choose Dr. Amal Khoury, 22 October 2026, a free time after morning visits (try 11:30, proceed only if policy/availability allows). Follow Patient → Doctor and time → Review and confirm; read source/clinic/time.
  7. Save and verify: Save locally · wait for sync means provisional. Open Sync & conflicts and wait for Confirmed by server. If Confirm booking appears, independently reread too. Reload calendar and record appointment ID; toast alone is insufficient.
  8. Edit: click confirmed card. Initial dialog says Cancel this appointment?; select Edit or reschedule, change time, Save changes. Same ID moves; original slot free; patient/doctor/clinic/source fixed.
  9. Undo: card → Cancel appointment → Undo inside 10-second countdown. Booking remains after reload. Do not reload during this countdown check.
  10. Cross-location: A and B at separate clinics try the prepared overlapping patient/time. Review conflicts, capture safe severity/redaction, select a suggested safe time and verify accepted outcome. See C4: patient warnings are not all hard blocks.
  11. Doctor: separate doctor profile → Network search, authorized synthetic name, Search, open correct record. Time N4; inspect consent limits, not just name match.
  12. Paper/evidence: reception Print day sheet for same date, inspect coverage/provisional labels → Print day sheet, cancel dialog or save synthetic-only PDF. Administrator records KPI window/calculation. No improvement claim yet.

Record blockers and confirmed IDs, then continue comprehensive checks. Destructive checks remain last.
